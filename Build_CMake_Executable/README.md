# CMake Project Builder Guide

## Project Structure
```
project_root/
├── CMakeLists.txt          # Main CMake configuration file
├── config.h.in             # Template for configuration header
├── include/                # Header files directory
│   └── config.h           # Generated configuration header
|   └── main.h             # header file for the source
└── src/                   # Source files directory
    └── main.cpp           # Main source file
```

## Basic CMakeLists.txt
```cmake
# Specify minimum CMake version required
cmake_minimum_required(VERSION 3.10)

# Define project name, version, and languages
# VERSION sets PROJECT_VERSION, PROJECT_VERSION_MAJOR, etc.
project(starter_project VERSION 1.0.0 LANGUAGES CXX)

# Print build information
message(STATUS "Building ${PROJECT_NAME} version ${PROJECT_VERSION}")

# Set C++ standard to C++20
set(CMAKE_CXX_STANDARD 20)
set(CMAKE_CXX_STANDARD_REQUIRED True)

# Create executable from source file
add_executable(main src/main.cpp)

# Generate config.h from config.h.in template
# Replaces @VAR@ with CMake variables in the template
configure_file(config.h.in ${CMAKE_SOURCE_DIR}/include/config.h)

# Add include directories to the target
# PUBLIC means the include paths are used by both the target and its dependents
target_include_directories(main PUBLIC
    ${CMAKE_BINARY_DIR}/include    # For generated files
    ${CMAKE_SOURCE_DIR}/include    # For project headers
)
```

## Configuration Header Template
The `config.h.in` file contains version information that CMake will configure:
```cpp
#pragma once

#define PROJECT_NAME "@PROJECT_NAME@"
#define PROJECT_VERSION "@PROJECT_VERSION@"
#define PROJECT_VERSION_MAJOR @PROJECT_VERSION_MAJOR@
#define PROJECT_VERSION_MINOR @PROJECT_VERSION_MINOR@
#define PROJECT_VERSION_PATCH @PROJECT_VERSION_PATCH@
```

## Build Instructions

### Prerequisites
- CMake 3.10 or higher
- C++20 compatible compiler
- Build system (Make, Ninja, or Visual Studio)

### Basic Build Commands

#### Method 1: Traditional Approach
```bash
# Create and enter build directory
mkdir build && cd build

# Configure
cmake -DCMAKE_BUILD_TYPE=Release ..

# Build
cmake --build .
```

#### Method 2: Modern Single-Step Approach
```bash
# Configure and build from project root
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

### Platform-Specific Commands

#### Windows (Visual Studio)
```bash
# Configure for VS 2022 64-bit
cmake -S . -B build -G "Visual Studio 17 2022" -A x64

# Build
cmake --build build --config Release
```

#### MinGW
```bash
# Configure
cmake -S . -B build -G "MinGW Makefiles"

# Build
cmake --build build --config Release
```

#### Ninja (Recommended)
```bash
# Configure
cmake -S . -B build -G Ninja

# Build
cmake --build build
```

### Running the Executable

```bash
# Unix/Linux/MinGW
./build/main

# Windows (Visual Studio)
.\build\Release\main.exe
```

### Cleaning

```bash
# Using CMake
cmake --build build --target clean

# Manual cleanup
rm -rf build            # Unix/Linux
rmdir /s /q build      # Windows CMD
```

## CMake Options

| Option | Description | Example |
|--------|-------------|---------|
| CMAKE_BUILD_TYPE | Build type | `-DCMAKE_BUILD_TYPE=Release` |
| CMAKE_CXX_STANDARD | C++ standard | `-DCMAKE_CXX_STANDARD=20` |

## Notes
1. cmake configuration is optional, only use it when you need cmake variable information inside the source file.
2. config.h will be generated by cmake while configuring.

## Best Practices

1. **Out-of-source builds**: Always build in a separate directory
2. **Build type**: Specify explicitly for single-config generators
3. **Parallel builds**: Use `-j N` flag with Make or Ninja
4. **Generator choice**: Prefer Ninja for faster builds

## Example Code

```cpp
#include <iostream>
#include <config.h>

int main() {
    std::cout << "Hello, CMake!\n";
    std::cout << "Project: " << PROJECT_NAME << " Version: " << PROJECT_VERSION << '\n';
    return 0;
}
```
